# 使い方ガイド同期スキル

アプリの**操作フロー**を変更したら、ユーザー向けの「使い方」表記が実装と食い違わないよう、
このスキルで**コードを正（source of truth）として**全箇所を同期更新する。

## なぜ必要か
過去に「自動変換」を実装した際、`app/page.tsx` の使い方は更新されたが `README.md` の
使い方は「一括変換ボタンをクリック」のまま取り残された。操作フローと表記のドリフトを防ぐ。

## Source of truth（操作フローの実体）
`app/page.tsx` の以下を読んで、ユーザーが実際に踏む手順を導出する：

- `<FileDropzone onFileSelect={setZipFile} ... />` … ZIP の選択／ドラッグ&ドロップ
- 自動変換 `useEffect`（`if (zipFile && !isConverting) handleConvert()`）の有無
  - **ある** → 「アップロード後、自動的に変換が開始されます（ボタン操作不要）」
  - **ない** → 「『一括変換』ボタンをクリック」
- 変換中ログ表示（`isConverting` / リアルタイム変換ログカード）
- 完了時の自動ダウンロード（`handleDownload` が呼ばれ `setZipFile(null)` でクリア）
- 「再変換」ボタン（`{(zipFile || isConverting) && <Button>...再変換</Button>}`）の有無

`components/file-dropzone.tsx` も、選択 UI の文言（ドラッグ&ドロップ/クリック）が変わっていないか確認する。

## 同期更新する対象（すべて一致させる）
1. **`app/page.tsx` の「使い方」リスト** … `<h2>使い方</h2>` 直後の `<ol>` 各 `<li>`
2. **`app/page.tsx` のアップロードカード説明文** … 「ZIPをドロップ／選択すると…」の補足文
3. **`README.md` の `## 使い方` 節** … 番号付き手順（1〜N）
4. （存在すれば）`CLAUDE.md` / その他ドキュメント中の操作手順記述

## 手順
1. `app/page.tsx` の操作フロー（上記アンカー）を読み、現在の手順を箇条書きで確定する。
2. 1 で確定した手順に合わせて、対象 1〜4 の文言を**互いに矛盾しないよう**書き換える。
   - 文言は簡潔に。手順の**意味（自動変換か手動ボタンか等）が実装と一致**することを最優先。
   - 「再変換」など補助操作は注記として残す。
3. `npx tsc --noEmit -p tsconfig.json` で型崩れが無いことを確認（JSX 編集の取りこぼし検出）。
4. 変更した使い方表記を、ユーザーに**差分（before→after）で**簡潔に報告する。

## 注意
- 「使い方」以外（リネーム規則・対応手続き種別ロジック等）は対象外。ただし
  `app/page.tsx` 内の「対応手続き種別ごとの処理ロジック」パネルの記述が、実コードの
  対応 ID（`lib/document-names.ts` の `SHAHO_NOTICE_TITLES`）と乖離していることに気づいたら、
  使い方の更新ついでに指摘する（自動では直さない）。
- コードを正とする。ドキュメントが実装より新しい/古いときは**実装に合わせる**。
